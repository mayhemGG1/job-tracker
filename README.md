# Job Tracker

Невеликий веб-застосунок на Flask для обліку заявок на вакансії. Кожен користувач реєструється зі своїм email і бачить лише власні заявки: компанія, посада, статус, посилання на вакансію та нотатки.

## Можливості

- Реєстрація та вхід (паролі зберігаються у вигляді хешів, `werkzeug.security`)
- Додавання, редагування та видалення заявок
- Статуси: `applied`, `interview`, `offer`, `rejected`
- Фільтрація списку за статусом
- Ізоляція даних: чужу заявку не можна ні побачити, ні змінити, ні видалити (відповідь `404`)
- Автотести на `pytest`

## Стек

- Python 3.14 (на ньому запускалися тести)
- Flask 3.1, Flask-SQLAlchemy 3.1, Flask-Login 0.6
- SQLite за замовчуванням (можна підставити іншу БД через `DATABASE_URL`)
- Jinja2-шаблони, без JavaScript-фреймворків

## Структура проєкту

```
.
├── app.py              # застосунок: моделі та маршрути
├── templates/
│   ├── base.html       # загальний шаблон, навігація, flash-повідомлення
│   ├── index.html      # список заявок + фільтр
│   ├── add.html        # форма нової заявки
│   ├── edit.html       # форма редагування
│   ├── login.html
│   └── register.html
├── conftest.py         # фікстури pytest (client, user, auth_client)
├── test_app.py         # тести
├── pytest.ini
└── requirements.txt
```

## Запуск

```bash
# 1. Клонувати репозиторій та перейти в папку проєкту
git clone <URL-репозиторію>
cd <папка-проєкту>

# 2. Створити віртуальне середовище
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Встановити залежності
pip install -r requirements.txt

# 4. Запустити
python app.py
```

Застосунок буде доступний на <http://127.0.0.1:5000>. Таблиці в базі даних створюються автоматично при першому запуску (файл `instance/jobs.db`).

## Налаштування

Конфігурація береться зі змінних оточення:

| Змінна         | Призначення                  | Значення за замовчуванням |
|----------------|------------------------------|---------------------------|
| `SECRET_KEY`   | ключ для підпису сесій       | `dev-only-change-me`      |
| `DATABASE_URL` | рядок підключення до БД      | `sqlite:///jobs.db`       |

> ⚠️ Значення `SECRET_KEY` за замовчуванням призначене лише для розробки. Для реального розгортання задайте власний ключ:
>
> ```bash
> export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
> ```

## Маршрути

| Метод      | URL                | Опис                                   | Потрібен вхід |
|------------|--------------------|----------------------------------------|:-------------:|
| GET        | `/`                | список заявок, `?status=` для фільтра  | так           |
| GET, POST  | `/add`             | створити заявку                        | так           |
| GET, POST  | `/edit/<id>`       | редагувати заявку                      | так           |
| POST       | `/delete/<id>`     | видалити заявку                        | так           |
| GET, POST  | `/register`        | реєстрація                             | ні            |
| GET, POST  | `/login`           | вхід                                   | ні            |
| POST       | `/logout`          | вихід                                  | ні            |

## Тести

```bash
pytest
```

Тести працюють з in-memory SQLite (`DATABASE_URL` підміняється в `conftest.py`), тому ваші реальні дані не зачіпаються. Покрито:

- порожній список, додавання, редагування, видалення, фільтр за статусом
- редірект на `/login` для неавторизованих користувачів
- заборону редагувати та видаляти чужі заявки
